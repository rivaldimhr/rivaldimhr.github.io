Manual QA project

Testing Virsila by hand, end to end.

Virsila is an interactive Pancasila learning web app with lessons, a practice game, a timed quiz and saved progress. I split it into modules and features, wrote positive and negative test cases for each, ran them, and reported 3 bugs with steps and evidence.

How I worked

The process follows the standard test process: plan, analyse, design, execute, report. There was no written specification, so expected results come from the app and its on-screen text.

  1. Break the app downExplored every screen and split the app into 8 modules and 31 features, one sheet per module.
  2. PlanSet scope, approach, environment, entry and exit criteria, and severity and priority scales.
  3. Design test casesFor every feature: positive cases first, then negative ones, each with pre-condition, steps, test data and expected result.
  4. ExecuteRan every case from a clean browser, at laptop size and at five narrower widths, recording the current result and status.
  5. Report bugsWrote each failure up with steps to reproduce, expected and actual results, impact, severity and a screenshot.
  6. SummariseCounted results per module and judged them against the exit criteria.

Test design techniques

Each test case in the workbook names the technique that produced it. Four examples:

Boundary value analysisThe nickname allows 30 characters, so I typed 29, 30 and 31. The exam activity is ticked from 70%, so I scored 60% and 70%. The timer warning starts at one minute, so I checked 01:01 and 01:00.
Equivalence partitioningOne correct and one wrong answer per quiz mode instead of every combination; keys A–D as the valid group and E, 5, 0 as the invalid one.
State transitionNot learned → learned → not learned; exam answer A → C; practice finished → retry → finished. The retry path is where BUG-001 was found.
Error guessingWhat if the saved progress is damaged? What if someone types HTML as their name? The first found BUG-003; the second passed.

Bugs found

All three are open. The full reports, with suggested fixes, are in the workbook.

BUG-001Severity: MediumPriority: HighFound by TCQUI010

Retrying only the wrong questions overwrites the best Latihan score with 100%

  1. Open Virsila with no saved progress and go to "Kuis".
  2. Click "Mulai latihan" and finish all 28 questions with 25 correct and 3 wrong (result 89%).
  3. On the result screen click "Ulangi 3 soal yang salah".
  4. Answer the three questions correctly and finish.
  5. Click "Pilih mode lagi" and read the best score under Latihan.
Expected
The best Latihan score stays 89%. A retry covers only the 3 questions that were wrong, so it should not count as a full practice score.
Actual
The retry result is 100% with the text "Skor terbaik baru untuk mode ini.", and the mode screen then shows "Skor terbaik: 100%" for Latihan.
Impact
A learner who got questions wrong sees a perfect best score, so the score no longer tells them or a teacher how well they know the material.

BUG-002Severity: MediumPriority: MediumFound by TCNAV003, TCNAV004

On screens up to 860 px wide the header hides four of the five section links and offers no menu

  1. Open Virsila in a window 390 px wide (or any width up to 860 px).
  2. Look at the header.
  3. Try to go to Sejarah, Praktik or Kuis from the header.
Expected
All five sections can be reached from the header, either as links or through a menu button.
Actual
Only "Progres" is shown. Lima Sila, Sejarah, Praktik and Kuis are hidden and there is no menu button. At 861 px all five links are shown.
Impact
Phone and tablet users, the main audience of a learning site for students, can only reach the quiz and the practice game by scrolling through the whole page.

BUG-003Severity: LowPriority: LowFound by TCPRG012

The page stays almost empty when the saved progress has the wrong shape

  1. Open Virsila, then DevTools → Application → Local Storage.
  2. Set the key virsila-progres-v1 to {"sila":null}.
  3. Reload the page.
Expected
The app ignores the damaged value and starts from 0%, as it already does for text that is not valid data (TCPRG011).
Actual
The hero shows no emblems, and the Lima Sila panel, the practice game and the quiz are empty. The console shows "Cannot read properties of null (reading 'includes')". The page stays broken on every visit until the stored value is deleted.
Impact
Rare for normal users, because the value has to be damaged first (for example by an older version of the app or a browser extension). When it happens the user cannot recover without clearing site data.
